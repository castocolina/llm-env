- Require **`min_wait` continuous idle seconds**, initially **300 seconds (5 minutes)**; no known in-flight request may remain.
- Wait at most **`max_deferred_wait` seconds**, initially **10800 seconds (3 hours)**; the maximum deadline is exclusive. Then defer without forcing a restart.
- **Do not add ingress/gateway/proxy/preload/sidecar services, instrumentation or a replacement request registry.** Do not change `pylib/compose.py` for activity tracking. No paid inference probes, automatic retries, notifications or zero-drop promises.
- Bash owns deployment lifecycle and observer scope creation; a bounded Python observer owns/reaps only its journal-reader descendants. Python application entrypoints use `uv run llmenv.py <subcommand>`; tests use established `uv run pytest`/`make test` paths. No new runtime dependencies.
- Implementation requires user approval after GPT 6.1 Sol review/fix rounds reach zero unresolved Critical/High, then a fresh Opus 5.5 HIGH evaluation. Production OmniRoute replacement remains excluded, including after implementation approval.
- Mandatory independent Laya round-1 assessment is recording against frozen snapshots. Preserve every original finding ID and checklist/impact severity; no label downgrade to terminate review. Every subsequent round also needs per-finding advisory receipts and full-model adjudication. Missing receipts block promotion, not document fixes. Do not overwrite the raw report or frozen inputs.

## Safety boundary — observation, not atomic admission control

Existing logs/counters supply a conservative gate, not an atomic reject-new-and-drain transaction. Arrivals can race final observation and shutdown, logger buffers can lag, and some routes are not covered by chat tracking. No zero interrupted requests or zero downtime claim is authorized. Require a complete window, final resample, supported deployment evidence and disposable boundary-arrival characterization. If absolute no-drop is required, stop for a user decision; do not restore an ingress guard or add sleeps as a substitute.

An unsupported deployment safely returns 75 even if all visible counts are zero. Useful eligibility is conditional on the capability evidence below, not on trusting a version string or the newer checkout. No profile is declared production-qualified by this design revision.

## Immutable image resolution (ORU-R1-003)

Capture the running container ID, image ID and its image's OS/architecture/variant. Normalize image IDs to `sha256:<64 lowercase hex>`; inspect platform rather than assuming host architecture or GPU identity.

1. Fetch the configured tag's **raw bytes once** with `skopeo inspect --raw docker://REFERENCE` into a private file. Compute its manifest digest using `skopeo manifest-digest FILE`; never hash JSON reserialization or strip bytes through shell command substitution.
2. For OCI index / Docker schema-2 list select exactly one matching runnable OS/architecture/variant descriptor, excluding attestations. Reject ambiguous variants, nested indexes and unsupported media types. Fetch the selected digest, verify the raw file's digest equals the descriptor, and extract its config digest.
3. For OCI / Docker schema-2 single manifests the initially fetched raw digest **is** the selected manifest digest. Extract config ID from those same bytes; do not re-read the tag. Reject schema-1 and missing/malformed config descriptors.
4. Both branches return the same immutable result: `repository`, `source_digest`, `manifest_digest`, `immutable_ref` (`repository@manifest_digest`), `config_id`, `os`, `architecture`, `variant`, and `kind` (`single` or `index`). Verify image-config platform after staging; mismatch is an error, never an alternate-platform guess.
5. Compare selected config ID with the running image ID, not the tag or index digest. Equal selected config is unchanged even if index/other-platform/release version changed. Release listings are informational only. Unresolved identity cannot authorize restart.
6. Stage only `immutable_ref`, verify its local config/image ID and platform, keep the old image. Staging does not move the configured tag. Never resolve a floating tag again during waiting or commit.

## Native-dependency preflight and replacement boundary (ORU-R2-001)

The updater does not support replacing a target container that has any stored incoming native Podman dependency. It must detect this and return 75 before moving a local tag, stopping/removing/creating a service, or otherwise mutating service lifecycle. Removing `depends_on` only from a replacement projection cannot clear dependencies already stored against the captured container ID. Do not recursively remove dependents (`podman rm --depend`), recreate siblings, migrate the existing topology, or invent a broad lifecycle exception. The repository's normal generated topology includes `remote-setup` depending on OmniRoute, so it is dependency-bearing and must defer; it is not an eligible replacement-success fixture.

Before candidate staging and again immediately before the first commit mutation, inventory the complete selected local Podman backend, not only the target project or running containers: obtain all container IDs from `podman ps --all --no-trunc`, inspect every ID with `podman container inspect`, and validate every inspected `Dependencies` array plus relevant create configuration and backend identity. Compare dependency IDs against the captured OmniRoute ID. Any incoming match, omitted/uninspectable container, command error, incomplete inventory, unknown inspect schema, malformed dependency ID/configuration, backend drift or inventory change means defer before mutation. Snapshot the complete ID/dependency/configuration inventory and recheck it at commit; any changed or uncertain state defers. Recheck is a guard, not an atomic lock over arbitrary Podman clients. An external actor can add a dependent after the final recheck; Podman may then refuse `rm` after OmniRoute has stopped. Do not force-remove, auto-rollback, claim atomicity, or hide this residual partial-commit risk.

A successful replacement procedure may be tested only on a separately constructed disposable deployment proven dependency-free by this same complete backend inventory and source-grounded fixture configuration. The success fixture must not be created by mutating/removing dependencies from the normal production topology and must not be represented as evidence that normal deployment updates are supported. The normal dependency-bearing deployment remains unsupported and deferred until a separately authorized migration or platform capability provides a verified safe path.

Select the inspected installed `podman-compose` executable directly, avoiding `podman compose` provider autodiscovery. Provider changes require renewed disposable proof. Use its `config` output as the starting normalized object, **not as proof that env_file/extends/binds are resolved**: installed `config` prints `merged_yaml` before dependency expansion (`2504–2800`, `4283–4291`). Support the generated plain compose shape only. Resolve supported bind paths against the original directory; validate all declared paths exist. Preserve original service fields except image and removal of `depends_on` in a projection only after the backend-wide preflight proves no incoming native dependency. Never write the main compose file.

Create a private 0600 projection in the invocation's 0700 directory:

- Exactly one service, `omniroute`, same `container_name`, explicit original project name, same ports/environment/health/grace/resources/restart settings. Image becomes the staged immutable reference. Remove dependencies only from this projection; all siblings remain outside it.
- Explicit service network aliases/attachments retained. Top-level referenced networks/volumes use `external: true, name: <inspected original resource name>`; compare network IDs and named-volume mount identity with the old container. No implicit new default network/volume is allowed. Reject pods/network_mode/links/volumes_from and unsupported resource forms.
- Fully literal serialized values: dollar-escape strings for the provider's second interpolation pass, use `--env-file /dev/null`, explicit `-p`, `--in-pod false`, and a controlled environment with provider/compose overrides removed. Resolve/check the projection again and compare semantic fields to baseline, allowing only image, dependency removal and explicit resource identities. Check that the replacement's project/service labels remain discoverable; projection config-file/working-directory and config-hash labels may differ and are not original-main-file provenance.

After final eligibility, with lock held, revalidate old ID/name/ownership, complete backend-wide dependency/configuration snapshot, and sibling/resource IDs immediately before the first mutation. Only a deployment with no incoming native dependency may cross this boundary. Commit consists of:

1. Retag the verified candidate ID to the agreed mutable configured reference (skip for manifest-pinned refs); preserve the prior tag target for recovery. Use the immutable reference in the projection regardless of this tag.
2. `podman stop --time "$stop_seconds" "$old_container_id"` using parsed original stop grace, then `podman rm "$old_container_id"` **without force or volume removal**. Check exit status and name absence; if an unexpected same-name container appears, fail without removing it.

Verify new ID != old ID, actual image ID == candidate config ID, original project/service labels, resource attachments and all sibling IDs unchanged, then healthy within validated `LLM_ENV_HEALTH_TIMEOUT_SECONDS` (existing default 60). This is not an eligible procedure for the normal dependency-bearing topology: its disposable acceptance is safe deferral with original OmniRoute ID/running state/local tag and sibling IDs unchanged. ## Capability and sanitized observer contract (ORU-R1-006)

A reviewed, checked-in **capability profile is evidence, not a request registry**. Bind it to exact running image config ID, inspected artifact hashes, server entrypoint/environment/logger destination, API schemas, route manifest and disposable fixture results. No version-only wildcard or operator 'assume safe' flag. Profiles list every reachable method/route/alias/upgrade and map it to arrival + in-flight + queue evidence, or prove it unreachable using existing deployment settings. Unknown/uncovered reachable family (including embeddings, media or WebSocket) means unknown for the **whole deployment**. An unconfigured provider or omission from `/v1/models` does not prove a route disabled. Do not change routing or settings to manufacture eligibility.

Profile selection additionally requires:

- Effective runtime logger level includes info (info/debug/trace), known structured stdout destination/format and reviewed buffering behavior; file-only, warn/error/silent, unknown env/entrypoint override or unknown transport defers. Inspect effective environment and artifact defaults, not just absence of `APP_LOG_LEVEL`. Never generate a paid request to test logging.
- Cursor-capable existing **journald** delivery for the captured container is the initial supported feed; other drivers defer until a separately proven adapter exists. `journalctl --output=json --no-pager CONTAINER_ID_FULL=ID` supplies `__CURSOR`, `_BOOT_ID`, `__REALTIME_TIMESTAMP`, `MESSAGE`; verify field shapes against disposable actual conmon records. Require readable cursor continuity and evidence for effective journald/conmon delivery policy (including rate limits/suppression). If loss cannot be detected or excluded for this deployment, defer. Do not change journald settings. A live `podman logs --follow` PID alone has no readiness/catch-up proof and is insufficient.
- Initial finite capture establishes the latest matching cursor; follow from that cursor. Each sample obtains a new finite latest-cursor barrier; only a reader that has consumed that cursor (or a bounded retained cursor set containing it) is caught up. No matching seed record, missing/vacuumed cursor, boot change, read error, dropped/suppressed records, unbounded backlog or cursor-set overflow means unknown. Silence with a valid unchanged cursor barrier is healthy, not evidence of disabled logging. Read raw records through pipes/memory only, no journal export files.
- Bound read records to 64 KiB and retained row/cursor hashes to 10000 each; exceeding either cap defers, never truncates to idle. Health/usage/API bodies are bounded to 8 MiB in memory. Persist only short hashes/scalars; these implementation memory caps are policy choices, not upstream limits.
- API GETs are `/api/usage/call-logs?limit=1000&offset=0`, `/api/usage/history`, `/api/monitoring/health` **without `deep=1`**. Cookies/raw bodies remain in memory; reauthenticate once on 401 within the same time budget. Any source missing/invalid is unknown. A full persisted page (>=1000 non-memory rows), unexplained ID loss/reset, stale/swept active row, source cap/eviction risk unaccounted for by independent in-flight evidence, schema change or ambiguous active-row truncation defers. Do not poll artifact-detail APIs or SQLite. Do not sum by-account and by-model duplicates.

Sanitized observer state schema v1 (all fields required): `schema`, `profile_sha256`, `container_id`, `started_at`, `boot_id`, `sequence`, `sample_monotonic`, `arrival_generation`, `row_generation`, `active`, `pending`, `admission`, `health_timestamp_ms`, `health_age_ms`, `feed_ready`, `barrier_seen`, `continuous`, `overflow`, `unknown`, `reason`. Generations/sequences are nonnegative monotone integers; counts are nonnegative integers (booleans are invalid). `admission` is the sum of activeHeavy/activeHealthyHeadroom/waiting/queuedBytes used only as a positive veto. `schema` is integer 1; readiness/continuity/overflow/unknown fields are booleans; `sample_monotonic` is a finite nonnegative number. Health timestamp/age are nonnegative integer milliseconds, or null only while unknown. `reason` is one of `ready`, `busy`, `capability`, `coverage`, `logging`, `feed`, `overflow`, `auth`, `schema`, `age`, `clock`, `continuity`, `deadline`, `ownership`, `lock`, `input`, `io`, never raw error text. No prompts, model/account names, keys, cookies, results or raw paths with suffix/query are persisted. Hash row IDs in memory before retaining; no new cross-request active registry.

Health freshness is deployment-specific and executable: profile gives source-verified `health_cache_ms` (1000 in the recorded deployed bundle; 30000 in the newer source, not automatically accepted) and fixture-measured `health_refresh_bound_ms`. Require refresh measurements for the exact artifact; absent evidence defers. Measure clock tolerance on this invocation's host before baseline: take 20 paired wall/monotonic readings and use the ceiling in milliseconds of the maximum bracket discrepancy plus measured clock resolution. Missing/invalid measurements defer; do not hardcode host skew/age allowances. At each GET bracket wall and monotonic clocks; request elapsed <=5000 ms, abs(wall elapsed − monotonic elapsed) <= measured `clock_tolerance_ms`, and `0 <= response_received_wall_ms - timestamp_ms <= health_cache_ms + health_refresh_bound_ms + clock_tolerance_ms`. Also check inter-sample wall/monotonic deltas for jumps against that tolerance. Future, backwards or nonadvancing timestamps past this bound are unknown; cached zeros never bypass arrival/pending checks. Quiet begins no earlier than the first observed health timestamp advance after reader readiness; this prevents starting on an indefinitely reused initial cache. Profile evidence must cover the stale-while-revalidate bound; cache TTL alone supplies no such bound.

Eligibility predicate: valid exact profile + complete, unchanged backend-wide native-dependency/configuration snapshot with no incoming dependency on the target + all required schemas/ages + caught-up continuous feed + unchanged deployment fingerprints + no overflow/unknown AND `active == pending == admission == 0`, with unchanged arrival/row generations for the whole window. Any incoming dependency or uncertainty defers regardless of quiet counts. Any positive count is busy even if another source is unknown; neither busy nor unknown permits replacement. Arrival parsing recognizes only exact profiled method/path, strips ` | ...` and queries before classification; unknown relevant methods/routes make coverage unknown. Loopback inference counts; health/auth/dashboard/OAuth/provider probes and internal fallback attempts do not reset quiet.

Representative sanitized fixtures: `active=1,pending=0` → busy; `pending.byModel={"synthetic":1},byAccount={...}` → pending=1, not 2; `chatAdmission.waiting=1` → busy; zero counts with logger warn → unknown; zero counts with uncaught barrier → unknown; zero counts with unprofiled POST /v1/embeddings → unknown; synthetic profile cache=1000, refresh bound=500, injected clock tolerance=250, age=1751 → unknown (maximum 1750); cache=30000 is accepted only with its own exact-artifact fixture evidence. These numbers test predicates; they are not fabricated measurements of the live deployment.

## Timing, process ownership and termination (ORU-R1-007)

```bash
min_wait="${LLM_ENV_UPDATE_IDLE_SECONDS-300}"
max_deferred_wait="${LLM_ENV_UPDATE_MAX_WAIT_SECONDS-10800}"
```

Initialize once; validate positive integers <=2147483647 and `max_deferred_wait >= min_wait` (explicitly empty overrides invalid). Reject overflow before arithmetic, including monotonic deadline addition. Messages/calculations use resolved values. Start monotonic wait budget **after staging**, `deadline = wait_started_at + max_deferred_wait`; `now >= deadline` always defers. Poll every 5 seconds, sleeping no longer than remaining time; activity never extends deadline. All API/log/metadata operations are bounded by the remaining budget; discard results completed at/after deadline. No historical idle credit. Busy/new arrivals/completions reset quiet to unset; begin it on the next complete nonbusy sample after all known work clears. Unknown or continuity loss defers, not reset-and-forget.

At `now - quiet_since >= min_wait` and `now < deadline`, immediately resample all sources plus barrier and fingerprints; new activity resumes waiting within the same deadline, unknown defers. Recheck the exclusive deadline immediately before the first mutation. After that commit boundary the health-verification budget is separate; expiration is never permission to force a busy restart.

Bash owns a single update-scoped worker **process group/session**, launched through a new project CLI supervisor, not a shell pipe with orphanable siblings. Supervisor spawns journal readers via argument arrays with `close_fds=True`, owns/reaps every child, selects nonblocking pipes, and never receives the update lock descriptor. Outer Bash keeps the flock FD; explicitly close it in observer/sampler/sleep/metadata subprocesses. A synchronous bounded Bash commit worker alone inherits it across the commit sequence; all Podman/provider children close it before exec so conmon cannot retain it. The commit worker may finish an already-started bounded sequence after outer-parent death, retaining exclusion until it exits. No persistent service/unit is added.

Before observer exec, close lock FD and detach with `setsid`; pass updater PID + `/proc/PID/stat` start tick + finite lifetime. Supervisor checks parent identity at most every 1 second (PID reuse does not count as alive). Set lifetime to remaining observation budget plus 10 seconds at launch, with child I/O bounded; on parent mismatch, lease expiry, TERM or normal exit, TERM all owned children, wait at most 2 seconds, KILL remaining children, reap and exit. This gives a **5-second post-parent-death bound under normal OS scheduling**, tested with SIGKILL of the Bash parent; stop/SIGKILL of the entire worker group is not cleanup machinery and is outside that guarantee. No guarantee against host suspension, kernel failure or externally killing the supervisor itself; those cases are explicitly outside this bound, not silently covered by shell traps. No stale lock inheritance by observers, even during their cleanup grace.

Pre-commit cancellation/death cannot retag or change services; only staged image/private files may remain after SIGKILL. Catchable exits clean temporary files; next invocation may remove only verified owned stale update directories, never arbitrary PID paths. **Death after commit begins is not transactional**: tag may move, old container may stop/remove, or replacement may run unverified. A subsequent invocation inspects reality and defers on missing/unhealthy service; it must not infer success, force restart or auto-rollback. Recovery instructions remain manual and production replacement remains unauthorized.

Exit outcomes: **0** unchanged/updated, **75** deferred/busy/unknown/lock contention, **1** invalid input or operational error. No config migration, main-compose rewrite, whole-stack lifecycle or automatic destructive rollback.
