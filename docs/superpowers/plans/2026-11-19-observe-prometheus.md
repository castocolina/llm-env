# Grafana-first Observe MVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a locally working Grafana dashboard backed by real Prometheus-format metrics for container resources and OmniRoute admission.

**Architecture:** A host one-shot reuses `resources.live_resources` (through `locate` injection) and `omniroute_activity` health access, emits fixed Prometheus series and posts once to VictoriaMetrics. A dedicated rootless Podman Compose project provisions Grafana and a separate user timer invokes the collector without touching the inference stack.

**Tech Stack:** Python standard library, existing `uv` CLI, Bash and systemd user units, rootless Podman Compose provider with external named secrets, VictoriaMetrics and Grafana.

**Spec:** [Grafana-first Observe MVP](../specs/2026-11-19-observe-prometheus-design.md).

**Fact anchors** (read directly, do not re-derive): `pylib/resources.py:441-505` (`_psi` builds flat `psi_{kind}_{window}` keys; `read_live` returns flat row keys with `events` as the only nested mapping), `tools/lib.sh:282-297` (`install_user_timer NAME "service desc" "timer desc" "script" TIMER-LINE...`; writes `Persistent=true`, `After=network-online.target`), `tools/lib.sh:6-7` (sourcing sets `REPO_DIR`/`CONFIG_PATH`), `pylib/resource_benchmark.py:31,55-58` (`CGROUP_ROOT=/sys/fs/cgroup`; cgroup from the `0::` line of `/proc/<pid>/cgroup`).

## Global Constraints

- No change to `make resources-snapshot`, main Compose generation/startup, installed healer, live `models.yml`, existing containers or their mounts/volumes. No original-stack restart at any time. `live_resources` keeps its existing callers (`cmd_resources` in `llmenv.py`, `interference.snapshot`); reuse it via the `locate=` injection point only.
- No credentials, API response bodies, call logs, or dynamic string labels in telemetry. All client HTTP requests stay on loopback; no proxy or redirects for the publisher. The Grafana admin password is delivered only through a rootless Podman external secret and never appears in Compose `environment`, `podman run` argv, printed output, or as a dependency of `down`/`status`. The external-secret long syntax `uid: '472'`, `mode: '0400'`, `target` is verified against the actual Grafana image (UID 472, mode 0400).
- The credential file is valid only when it matches `^[0-9a-f]{48}$`. A valid file is never regenerated on `up`; a new password is generated only when both the named secret and the credential file are absent. An **invalid file (with or without the secret) or a missing file beside an existing named secret is a hard failure before any generation or start** — never silently mint a second password and never overwrite a bad file. No failure changes the credential file or volumes; no normal `up`/`down`/`status` deletes the secret.
- No permanent custom collector process, additional Python dependencies, or new Make targets. No image/port override on production commands. Do not enable the global `podman-restart.service`; the timer skips quietly when the metrics backend is down.
- Storage: metrics retention 365 days, VictoriaMetrics free-space floor 100 GB. No hard 2 GB storage cap is promised (that rule belonged to the retired JSONL store). The 512 MiB / 1 CPU caps on the new containers are boot-probed values, not a capacity recommendation, and are deliberately excluded from `pylib/resources.py` `DEFAULT_POLICY` and `make resources-snapshot`.
- Check in tests and run `make validate && make test` after Python edits. During implementation use `uv run pytest tests/test_observe_metrics.py -q` and `uv run pytest tests/test_observe_stack.py -q` for targeted checks. Stub external services in tests; never touch the owner's user units, live config, ports, or volumes from tests. `LLM_ENV_SCOUT_OUT` is not used here; scratch stays under `./tmp/`.
- Stop/go: same OmniRoute container ID, mounts and health before and after; no main-stack stop/restart. Never delete volumes or the Podman secret. Record host-local time: do not start a new deployment after 21:45 local; if incomplete by 21:55, roll back only the monitoring project and verify inference. No merge or push.

## Review Focus

- Flat PSI key, real zero versus missing/mistyped/nonfinite value: renderer tests feed a real `read_live`-shaped row with flat `psi_full_avg300` and assert the gauge is emitted, while gaps are omitted and `events` is the only nested mapping.
- Sensitive diagnostics and stale health: health tests assert secret-free fixed errors, the exact allowed metric names, and that a stale or all-fields-missing health document returns `None` (a test distinct from priming).
- One timed-out source / hung worker versus a usable peer: collector tests use a short injected deadline and a blocked worker (released in `finally`) and assert the hung result is ignored, its `unavailable` set is never read, the peer stays complete, and `containers_incomplete=True` when the container worker hung.
- Credentials and lifecycle crossing into production: stack tests assert the external-secret long syntax, no password in argv/output, `down`/`status` with no credential file, the hard failures for an invalid file (with and without the secret) and for a missing file beside an existing secret, generation only when secret and file are both absent, a valid file never overwritten, and no `podman-restart.service` enable.
- Runtime configuration that parses but does not work: Task 3 proves real 204 ingestion, Grafana's authenticated data-source/dashboard APIs, and the exact `mem_limit: 512m` / `cpus: 1.0` cgroup state of the two new containers.

### Task 1: Produce and publish Prometheus metrics

**Files:** Create `pylib/observe_metrics.py` and `tests/test_observe_metrics.py`; modify `llmenv.py`.

**Interfaces:**
- `render_metrics(live: Mapping[str, Any] | None, health: Mapping[str, Any] | None, *, containers_incomplete: bool = False) -> str`. `live` is the **already-filtered** per-service mapping (unknown rows removed by the collector); `None` means the whole container worker failed or timed out. `health` is a fresh parsed health doc, or `None` when that source is down or timed out. `containers_incomplete=True` means at least one configured container's inspect failed/timed out, or the whole container worker hung. Never serialize arbitrary field names or values. `llm_env_source_up` carries only the `source` label (`containers` / `omniroute`) and is emitted for **both** sources on **every** call: 0 when `live is None or containers_incomplete` (containers) / `health is None` (omniroute), else 1. Every other family carries only a `service` label: container families use the enabled names from `pylib.resources.LIVE_CONTAINERS`; **all health families use the single fixed label `service="omniroute"`**. For a running row emit `running=1` plus whatever other valid fields are present; for a confirmed-stopped row (`state == "not running"`, i.e. a successful inspect whose State.Running token was the literal `false`) emit only `running=0` and no other samples; an unknown row (inspect error/timeout/malformed state) is absent from `live` and emits nothing. Omit `None`, booleans, non-numbers, nonfinite numbers and missing fields; include valid zero. End with a newline and emit `# TYPE` per present family.
  - Container gauges (sources are the flat keys of a `read_live` row): `llm_env_container_running` (synthetic from state), `llm_env_container_memory_current_mib` (`current_mib`), `llm_env_container_memory_peak_mib` (`peak_mib`), `llm_env_container_memory_cap_mib` (`cap_mib`), `llm_env_container_memory_swap_mib` (`swap_mib`), `llm_env_container_cpu_avg_cores` (`cpu_avg_cores`), `llm_env_container_memory_psi_full_avg300` (`psi_full_avg300` — a **flat** key, built by `_psi()` as `f"psi_{kind}_{window}"`; there is no nested `psi` mapping), `llm_env_container_uptime_seconds` (`uptime_s`), `llm_env_container_vram_mib` (`vram_mib`). **`events` is the only nested mapping**: counters `llm_env_container_memory_events_max_total` (`events.max`) and `llm_env_container_oom_kills_total` (`events.oom_kill`). `cpu_avg_cores` is `usage_usec / 1e6 / uptime` since container start — a **lifetime average** that flattens after long uptime, not current load; say so in the `# HELP` text and the dashboard panel.
  - Health gauges: `llm_env_omniroute_active_heavy` (`chatAdmission.activeHeavy`), `llm_env_omniroute_waiting` (`chatAdmission.waiting`). Health counters: `llm_env_omniroute_chat_sheds_total` (`chatAdmission.shedTotal`), `llm_env_omniroute_guard_rejects_total` (`adaptiveAdmission.pressureGuardRejectCount`). All four use `service="omniroute"`; omit any single missing field; `read_omniroute_health` returns `None` when all four are missing.
- `read_omniroute_health(port: int, password: str, *, deadline_s: float = 10, clock=time.monotonic, sleep=time.sleep) -> dict[str, Any] | None`. One 10-second deadline from `clock()`. Reuse `bounded_login`, `bounded_get`, `PRIME_GAP_S` (0.2 s) and `epoch_ms` from `pylib.omniroute_activity`: login, prime GET of `/api/monitoring/health` (discard body), `sleep(PRIME_GAP_S)`, second GET, parse JSON. Parse `.timestamp` with `epoch_ms` (integer epoch ms or RFC 3339 UTC string). With `wall_ms = int(time.time() * 1000)` taken at the second GET, accept `age_ms = wall_ms - ts` in `[-2000, 35000]` (age <= 35 s, future skew <= 2 s). If stale, `sleep(1)` and do one further GET + re-parse + re-check, still inside the same 10 s deadline (no extension). Any `Deferral`, `ValueError`, `TypeError`, `KeyError`, `AttributeError`, missing/unparseable `.timestamp`, all four recognized metric fields missing, or still out-of-range after the retry returns `None`. Never log token, password or body.
- `collect_metrics(limits: Mapping[str, Any], pci: str | None, *, port: int, password: str, deadline_s: float = 25) -> str`:
  - Local locator, no shared cache, no change to `pylib.resources._locate`: closure `locate(container: str) -> tuple[Any, int, float] | None` with an `unavailable: set[str]` owned by the container worker. One `subprocess.run(["podman", "inspect", "--type", "container", "-f", "{{.State.Running}} {{.State.Pid}} {{.State.StartedAt.Unix}}", container], capture_output=True, text=True, check=True, timeout=5)` (`--type container` is safe and prevents matching other object types).
  - Interpret the State.Running token strictly: the literal `true` means running — read `/proc/<pid>/cgroup`, take the `0::` line, set `cgroup = CGROUP_ROOT / line[3:].lstrip("/")` (same construction as `pylib.resource_benchmark.cgroup_dir`), and return `(cgroup, pid, started)`; the literal `false` means confirmed stopped — return `None` **without** adding to `unavailable`. **Anything else** (empty, malformed, extra tokens) and any `TimeoutExpired`/`CalledProcessError`/`OSError`/parse/cgroup-read failure means **unknown**: `unavailable.add(container)` and return `None`.
  - `raw = live_resources(limits, pci, locate=locate, now=time.time())`; then `live = {svc: row for svc, row in raw.items() if LIVE_CONTAINERS[svc] not in unavailable}` and `containers_incomplete = bool(unavailable)`.
  - Two daemon workers under one shared `deadline_s`, each returning an **immutable snapshot through its own one-item `queue.Queue`** (equivalently: a private result object the main thread reads only after a successful join). The container worker computes the snapshot and filtering above and puts `(live, unavailable)`; the health worker puts `read_omniroute_health(...)`. Join each with the remaining deadline. **The main thread ignores a still-running worker even if it later returns, and never reads that worker's `unavailable` set**: on `join` timeout set `live=None` and `containers_incomplete=True` for the container worker (discard its snapshot entirely), and `health=None` for the health worker; keep the other source's complete snapshot. Render **once** from these frozen locals: `render_metrics(live, health, containers_incomplete=containers_incomplete)`.
  - Deterministic gate test: inject a short `deadline_s` (e.g. 0.05) and a worker blocked on a `threading.Event`; assert the hung worker's result is ignored even if it later returns, the peer source stays complete, and `containers_incomplete=True` if the container worker hung. Release the Event in the test's `finally` so no thread leaks.
- `publish_metrics(text: str) -> None`: fixed `http.client.HTTPConnection("127.0.0.1", 8428, timeout=5)` POST to `/api/v1/import/prometheus`, `Content-Type: text/plain; version=0.0.4`; close connection, accept only 2xx (VictoriaMetrics returns 204), never log response text.
- CLI `uv run llmenv.py observe-metrics [--push]`: `cfg = require_valid_config(load_config(Path(args.config)))`, `limits = limits_for(cfg, host_resources())`, `pci = (cfg.get("gpu") or {}).get("pci_address") or None`, `port = cfg["omniroute"]["port"]`, `password = cfg["omniroute"]["initial_password"]` (exact keys of `llmenv.py:450,656-660`). Default mode prints only exposition text and exits 0, including when both sources are down (status samples are still valid exposition). `--push` publishes the same text, is silent on 2xx and exits 0 even with both sources down. **Every dispatched-command error in either mode** (config/argument-value failure, collection failure, publish failure, any other exception in the handler) prints only the fixed stderr line `observe-metrics: collection or publish failed` and exits 1 — never the invalid config's secret text and never the JSON `fail()` output. argparse usage errors (exit 2, usage text) are **out of scope**: they are raised by `build_parser().parse_args` before dispatch and are not wrapped.
