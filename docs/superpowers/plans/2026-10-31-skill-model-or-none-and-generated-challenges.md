# onboard-local-model: One Model or None, and Generated Benchmark Challenges Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The project-local skill `onboard-local-model [<model>]` takes either one model (a `models.yml` alias, a Hugging Face repo or URL, or a local GGUF file) and verifies and fit-checks that one, or takes none and scouts Hugging Face, researches the best candidates for this host and decides with other skills and agents (advisory `jev-fast-decision` items, parallel research subagents, a deep-research style skill when installed). Its quality ladder runs on challenges generated per run: seeded defect injection over correct reference projects, five difficulty layers, each challenge proven to fail as shipped and to pass with the reference fix before any model sees it, generated into an isolated directory under `./tmp/` with its own git repository, run by a delegated script, verified from a pristine copy, and compared head-to-head on one seed set across candidates and quants (for example Q4_K_M vs Q5_K_M).

**Architecture:**
- The generator is node ESM under `.claude/skills/onboard-local-model/challenges/` (no npm dependencies), driven by `scripts/gen-challenge.sh`. Bash validates arguments, enforces the `./tmp/` rule (`require_tmp_out`) and makes the git repository; node instantiates a reference project, injects one seeded defect, runs the validity gate and writes `DIR/challenge/` plus `DIR/manifest.json`. The reference solution is re-derived from the seed, never stored next to the challenge.
- `effort-run.sh` consumes generated challenges by default (the five bundled `tasks/l*/` stay as the offline regression set behind `--challenges bundled`), writes the seed set it used to `seeds.json`, generates and gates every challenge before the first agent run, hash-checks the pristine copy before and after each run, and flags a run whose transcript names the skill directory, the run's `challenges/` directory or `manifest.json`, or that changed a guarded file of the repo (Decision 9; a tripwire, not a sandbox). `score.sh` excludes flagged runs, scores layers by majority when a layer has several challenges and reports the `challenge_set`; `compare-runs.sh` refuses to compare runs whose challenge sets differ.
- Input handling: `resolve-target.sh` classifies the argument (and, for an alias or a local GGUF, writes the redacted scratch config step 4 needs); `hf-scout.sh --repo` screens one named repo; `rank-candidates.sh` gates and ranks the no-argument shortlist from research evidence cards, with jev answers as advisory disagreement flags; `references/selection-criteria.md` section 7 holds the criteria and the research brief; `references/challenges.md` holds the generator, gate, calibration, anti-contamination and head-to-head rules.
- Everything lives in the untracked skill tree and its untracked tests (rule below). The only tracked edits are one README sentence, its doc test, and this plan's index row.

**Tech Stack:** bash + shellcheck, node >= 20 ESM (`node:test`, `node:assert/strict`, `node:fs`, `node:path`, `node:url`, `node:crypto`, `node:child_process`; host has v24.21.0), jq 1.8.2, yq, git, pytest (+ xdist), ruff, pyright, Hugging Face Hub API (read-only GETs).

**Spec:** the owner requirement given to the plan writer on 2026-10-31 (restated in Goal, Decisions and the Generator contract below, so the plan stands alone). Related plans, not edited here: `docs/superpowers/plans/2026-10-30-focused-start-and-llama-toggle.md` (DONE) and `docs/superpowers/plans/2026-10-30-local-combo-and-capacity.md` (implemented on `main` through its Task 10). Names reused unchanged: `make stop-llama`, `make start-llama`, `make llama-enable MODEL=<alias>`, `wait-gpu-release.sh`, `bench-fit.sh`, `tune-sweep.sh`, `quant-headroom.sh`, `effort-run.sh --layers`, `score.sh` keys `ladder`/`ladder_at`/`by_layer`/`pass_rate`/`tool_use`/`invalid_runs`, the capacity card `ladder` section, `require_tmp_out`, `LLM_ENV_SCOUT_OUT`, and the test helpers `_run`, `_out`, `_md`, `_section`, `_row`, `_score`, `_stub_bin`, `_effort_run`.

## Decisions (open questions resolved with defaults)

1. **Generator language and boundary.** Node ESM `.mjs` (the challenges are node projects, so the gate runs `node --test` natively); `scripts/gen-challenge.sh` is the only entry point the skill and `effort-run.sh` use. No Python helper is needed, so no `llmenv` subcommand is added.
2. **Library.** Seven correct reference projects, several serving more than one layer, plus a pool of ten decoy modules (Generator contract, "Library"). Five reuse the bundled tasks with their reference fixes applied (paginate, lru-cache, log-parser, currency-invoice, event-pipeline); two are new (stats, shipping-quote). The bundled `tasks/` stay unchanged as the regression set.
3. **What a seed changes.** Project, site or feature, operator, identifier renames (always applied), seeded fixture cases (paginate, stats, log-parser) and, at L5, the decoy selection and an optional twin decoy. Each project's fixed tests must fail on every declared mutation, so the library check at seed 1 shows that every seed's challenge fails as shipped (the reference passes by construction: fixtures take their expected values from it); fixtures add variety, and up to 8 deterministic attempts are a safety net.
4. **Seeds.** Unsigned 32-bit integers. Every random decision draws from `mulberry32(fnv1a32("a<attempt>/<label>") ^ seed)`; labels: `project`, `item`, `op`, `renames`, `fixtures`, `decoys`, `twin`. Fresh seeds come from `/dev/urandom` per run unless `--seeds FILE` is given.
5. **Generator id.** `g-` plus the first 12 hex digits of sha256 over the sorted `challenges/` tree (`<relative path>\0<content>\0` per file). It is recorded in every manifest, `seeds.json` and result row; any library edit changes it, and a seed set from another generator id is refused.
6. **The reference never sits next to a challenge.** The gate builds the reference and the challenge in `DIR/.gate/` and removes it in `finally`; `--with-reference` keeps `DIR/reference/` only for tests and post-run diagnostics, and `effort-run.sh` never passes it. The manifest holds ids, counts and hashes, never source text.
7. **effort-run defaults.** `--challenges generated` (default) or `bundled`; `--per-layer K` (1..10, default 1) or `--seeds FILE` (exclusive); `--tasks` only with `bundled`. A head-to-head uses `--per-layer 3` once and `--seeds` for every other lane.
8. **Ladder with several challenges per layer.** `ladder_at[L]` is the lowest effort tier at which a strict majority of layer L's distinct challenges were solved (null if none); the denominator is the number of distinct challenges (tasks) of layer L among the valid rows (all tiers; `api_error` and `leak_suspect` rows excluded first), the numerator the distinct challenges solved at that tier. A layer counts toward `ladder` when `ladder_at[L]` is not null. With one challenge per layer this equals today's rule, so the existing score tests stay unchanged.
9. **Leak flags (a tripwire, not a sandbox).** A row is `leak_suspect: true` when (a) its transcript contains the skill directory's absolute path, the run's `challenges` directory absolute path or `manifest.json`, or (b) a guarded file changed during the run (`outside_writes`, sorted, at most 20 paths relative to the guard root). Guard root: `ONBOARD_GUARD_ROOT`, default `REPO_DIR`; it must be a git work tree (else `effort-run.sh` exits 2 before generating, naming `git work tree`). Guarded files: the guard root's git-visible files, `git -C <root> ls-files -z --cached --others --exclude-standard` (tracked files plus untracked files no ignore rule excludes, so `tmp/`, `.venv/` and the caches are out by the repo's own rules), minus the tool-state paths `.codegraph/`, `.pi/`, `.superpowers/`, `.playwright-mcp/` and everything under `.claude/` except `.claude/skills/` (excluded by name because some are ignored only through `.git/info/exclude` or the global ignore file, Fact 16, which another checkout may lack). The listing is taken right after the stamp file is touched and again after the agent; a path counts when it is in the second listing and newer than the stamp, or in the first listing and no longer exists. Not detected (stated in `references/challenges.md`): reads or writes of sibling run directories under the out directory (inside `tmp/`), reads that never name the paths in (a), and anything outside the guard root. A concurrent writer (another session editing a guarded file) also flags the row, so a live benchmark runs with no other writer on the repo, and a flagged lane is re-run on the same seeds. `score.sh` excludes those rows and counts them as `leak_suspect_runs`. A pristine challenge whose hashes no longer match its manifest (before or after a run) aborts `effort-run.sh` with exit 1.
10. **Comparability.** Two result files are a head-to-head only when `score.sh` reports equal `challenge_set` objects (`generators`, `tasks`, `efforts`, `timeouts`); `compare-runs.sh` exits 3 otherwise.
11. **Argument precedence (`resolve-target.sh`).** (1) an existing regular file ending in `.gguf` (any case) is `gguf_file` (it must start with the bytes `GGUF`); (2) an `http(s)://` URL on `huggingface.co` or `hf.co` is `hf_file` when it names `resolve/<rev>/<path>.gguf` or `blob/<rev>/<path>.gguf` (query string dropped), else `hf_repo`; another host is an error; (3) an exact alias in `models.yml` is `alias`; (4) any other argument ending in `.gguf` (any case) exits 2 with `not found` (a mistyped relative path such as `Downloads/Foo-Q4_K_M.gguf` must never become a repo id); (5) `<org>/<name>` matching `^[A-Za-z0-9][A-Za-z0-9._-]*/[A-Za-z0-9][A-Za-z0-9._-]*$` is `hf_repo`; (6) anything else exits 2 naming the four accepted forms.
12. **No-argument ranking.** Hard gates first (fit class `vram` or `offload`, pick at least 3.5 bpw, native context at least 131072 from the scout; tool-calling template, architecture supported by the pinned llama.cpp image, no red flags from the research card), then the weighted sum of five 0-3 levels (`agentic_evidence` x3, `speed` x2, `context` x2, `lab` x1, `recency` x1; max 27), ties broken by the smaller pick size. At most 6 candidates are researched and at most 3 shortlisted. jev answers never enter the arithmetic: a jev level that differs from the card by 2 or more, or a `needs_fallback`, is listed under `disagreements`, and the orchestrator re-reads that evidence before deciding.
13. **Research subagents.** One per shortlisted candidate, dispatched in one message (parallel), on the session's default model (the work is judgment, not mechanical), read-only, each writing one evidence card. A deep-research style skill, when the session lists one, runs once per no-argument run for the landscape question before scouting; its findings become extra `--query` terms and evidence rungs 2-4, never measurements.
14. **Own-code audits.** `ponytail:ponytail-review` runs on diffs of this skill's own scripts and library; `reducing-entropy` only when the owner asks (it is manual-only). Neither ever runs on the owner's other code or during a benchmark.
15. **Prompts.** Generated prompts start with `Work only inside this directory.` and end with the bundled tasks' shared sentence; L3 and L5 prompts never name the file that holds the cause. Bundled prompts are unchanged.
16. **Gate timeouts.** Each test file runs with a timeout of `ONBOARD_GEN_TEST_TIMEOUT_MS` (default 20000); a timeout in the reference is a library error, a timeout in the challenge makes the attempt invalid. The variable only affects the failure path, never a valid challenge's bytes. Each run is an asynchronous `spawn(process.execPath, ["--test", "--test-reporter=tap", <absolute test file>], { cwd, detached: true })` (its own process group; never a bare `node` from `PATH`, never `spawnSync`), and a timeout kills the whole group (`process.kill(-child.pid, "SIGKILL")`), so the per-file child `node --test` starts dies with it.
17. **Tracked edits.** `README.md` (the ladder sentence) and `tests/test_docs.py` (one new test) are committed in Task 11; the plan index row stays uncommitted with the index's other pending edits.
18. **Anti-contamination rules** (copied into `references/challenges.md` by Task 11):
    - Challenges come only from `gen-challenge.sh` (library plus seed) or `tasks/`; never from a transcript, diff or answer of any model under test, and never from the owner's repositories or working trees. `gen-challenge.sh` takes no input file.
    - Each run draws fresh seeds unless it is a lane of a head-to-head, where every lane uses the same `seeds.json`; partly overlapping seed sets are never compared.
    - Seeds whose challenges the orchestrator inspected to debug or tune a lane are burned for that lane's evaluation; a seed set sent to a cloud lane is retired after that comparison. Burned seeds may only reproduce an old result.
    - The reference solution is never on disk during an agent run; leak-suspect rows never count; a library edit retires every older seed set (the generator id changes).
19. **Head-to-head protocol** (copied into `references/challenges.md` and referenced from SKILL.md steps 7 and 9, `tuning.md` Q8 and `anchors.md`): (1) the first lane runs `effort-run.sh --per-layer 3` and its `seeds.json` is the set; (2) every other lane (candidates, baseline, quants of one model such as Q4_K_M vs Q5_K_M, anchors) runs `--seeds <that file>` with the same `--efforts`, `--timeout` and client profile, one lane at a time, each served through its own gated swap; (3) `compare-runs.sh` over all result files (anchors with `--correctness-only`); a lane with `invalid_runs` or `leak_suspect_runs` above 0 is re-run on the same seeds per the retry ladder before comparing; (4) decide with SKILL.md step 9; (5) retire the set.
