## Lesson from the earlier sessions: the idle-CPU busy-spin (found in the transcripts, 2026-11-20)
- Source: Claude session `7cc92ce1` (2026-10-11 to 2026-10-12, Laya provisioning), messages of 2026-10-11T23:36 and 2026-10-12T03:17; pin documented in `docker/system-one/Dockerfile` lines 5-7 and in `.claude/skills/system-one-scout/` (`SKILL.md:52`, `references/upgrade.md:39`).
- Bug: with torch 2.15.0 on the `rocm7.14` wheel index, ROCR 1.21's `AsyncEventsLoop` busy-spins ONE CPU core forever after the first GPU kernel (ROCm/rocm-systems#12674, ROCm/TheRock#7051). Laya (PyTorch, ROCm) burned 100 % of a core at idle with 12 ms p50 latency, so latency tests never showed it.
- Component taken from a previous version: the PyTorch ROCm wheel index `rocm7.2` (torch 2.14.1+rocm7.2) instead of the newest; idle CPU 0 %, latency 12.3 ms; image also pruned to gfx1201 kernels (18.2 GB to 9.24 GB). Rule kept in the skill: never move the pin by version number; only with a released fix and an idle-CPU check ("after an inference, idle CPU below 5 % of a core and p50 at most 20 ms; if not, stop and report").
- It did not affect llama.cpp (Vulkan backend, no ROCm); the Aug 2026 ornith 9B runs showed GPU 100 % and CPU almost idle. Current measurement: Laya idle CPU 0.0083 cores (30 s delta of `cpu.stat`, 2026-11-20 16:1x).
- Consequence for this plan: (1) the lifetime-average CPU gauge cannot show a busy-spin, so a real interval CPU metric is added (task T1c in the companion plan); (2) every bring-up of a model container ends with an idle-CPU gate (L3); (3) llama.cpp is kept on the Vulkan image (a ROCm image is not used).

Acceptance includes a test with a fake router proving that an unloaded alias is never requested and that a loaded one is scraped with the bearer; and a live check on the pinned image (b12004) that the router's model-list call itself does not load anything (read `podman logs` for a load line before/after).
